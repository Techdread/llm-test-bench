Under the hood

How it’s built

The same conventions run through every app, which is what lets one person keep 220+ of them working.

No build step

Native ES modules with Preact and HTM through import maps. No bundler, no transpiler: the source you read is the code that runs.

Provider-agnostic models

One streaming layer over OpenRouter, LM Studio and other OpenAI-compatible servers, with local coding agents (Claude Code, Codex and others) exposed as ordinary model choices in the private hub.

Local-first storage

Work is saved to a folder you choose, through the File System Access API. Saves are append-only, so nothing a model generated is ever overwritten.

Verify, don’t trust

Generated code runs in sandboxed frames and is measured: rendered, screenshotted, re-read by the model, or entered into an emulated XR session.

Vendored, pinned dependencies

Every library is served from this site and recorded in a manifest. Engines copied into generated projects are checked against pinned hashes.

Zero-npm testing

Unit tests on node:test, plus recorded user-flow replay and visual-regression screenshots driven by a small Chrome DevTools Protocol client.

Trying the projects

Your data, your models

The site is hosted, but your work is not uploaded to it. In Chrome or Edge, choose a folder on your own computer and the apps read and write inside it with your permission.

  1. Choose a folderThe browser remembers it and asks before restoring access.
  2. Connect a modelYour local LM Studio or OpenAI-compatible server, or your own OpenRouter key.
  3. Open a projectPrompts go only to the provider you pick; outputs stay in your folder.
